# 中文 Agent 体验站设计

本方案将现有购物 Agent 演示扩展为可通过域名访问的中文体验站。用户直接进入聊天，后台使用匿名身份关联对话与长期记忆。展示重点是需求理解、商品检索、比较、规划和个性化推荐。

本文描述目标行为与实现约定，不表示这些能力已经全部实现。已确认需求、仓库现状和建议默认值分别列出。

当前实现、测试证据和真实部署的待验收项见 [实现与验证](agent-experience-verification.md)。下文“仓库现状与设计压力”记录设计时的基线，不作为当前实现状态。

## 已确认需求

- 用户打开域名即可使用，不提供注册、账号登录、邮箱或验证码流程。Supabase 管理后台匿名身份及访问凭证。
- 界面、商品内容、Agent 回复和生成卡片使用中文，中文查询能够稳定检索商品和政策。
- 商品数据和图片在演示前生成、校验并固化。商品、品牌和人物遵循仓库的虚构约定，商品使用 ACME 系列。
- 对话历史和长期记忆持久化。已完成的对话在刷新页面、服务重启或重新部署后可以恢复。
- 同一匿名用户的不同对话分别维护历史、短期上下文和当前任务，共享长期记忆。不同匿名用户的数据隔离。
- 前台不显示“已记住”、记忆列表、记忆计数或读写状态。记忆通过推荐结果和减少重复询问体现。
- 不要求跨设备恢复身份，也不要求清除浏览器数据后找回原身份。
- 购物车和结算保留演示性质，`checkout` 不创建真实订单或扣款。

图片生成按用户确认暂缓，不阻塞其他内容。本次保留现有图片和生成提示清单，补齐中文数据与展示功能；新增图片仍按下文素材规范接入。

## 身份与对话生命周期

`user_id` 标识匿名访问者，来自有效的 Supabase 凭证。`conversation_id` 标识该访问者的一段对话。两者承担不同职责；对话 ID 本身不授予访问权限。

| 用户行为 | 目标行为 |
|---|---|
| 首次访问 | 创建匿名身份和首段对话，直接进入助手 |
| 同一浏览器再次访问 | 恢复已有身份和历史入口，可继续此前对话 |
| 同一浏览器打开多个标签页 | 复用同一匿名身份，各标签页可以打开不同对话 |
| 新建对话 | 创建新的对话记录，保留旧历史和该用户的长期记忆 |
| 打开旧对话 | 加载历史展示内容及该对话的工作上下文 |
| 另一个独立浏览器环境访问 | 创建另一匿名身份，使用独立的数据 |
| 清除浏览器身份数据 | 此后可能创建新身份；不因此删除服务端的旧数据 |

前端先恢复现有凭证，仅在确认没有可用匿名身份时创建身份。页面重复挂载、并发初始化或暂时的网络故障不能造成重复创建或身份重置。访问凭证失效与服务暂时不可用分别处理。

匿名身份的浏览器恢复边界见 [Supabase 匿名身份说明](https://supabase.com/docs/guides/auth/auth-anonymous)。

| 长期记忆已有存储接口、事实校验、提取、召回和清空版本机制，演示使用本地 JSON | [memory.py](../commerce-common/commerce_common/memory.py)、[main.py](../examples/assistant/api/main.py) | 复用规则，接入 PostgreSQL 存储 |

| 最终卡片由服务端校验、补全后通过 `ui` 事件发送 | [presentation.py](../commerce-common/commerce_common/presentation.py)、[enrichment.py](../shopping-agent/core/shopping_agent/enrichment.py) | 归档最终展示内容，支持原样恢复 |
| 商品库有 87 个主商品、21 个规格变体、11 个分类；9 个主商品有图片，33 个有完整详情 | [catalog.json](../examples/assistant/data/catalog.json) | 优先补齐内容和场景内可比较的差异 |
| 搜索分词只匹配英文和数字，前端列表读取最多 100 个商品 | [storefront_fixtures.py](../examples/demo_common/storefront_fixtures.py)、[api.ts](../examples/assistant/storefront-web/lib/api.ts) | 支持中文检索；数量扩大时增加分页 |
| 记忆技能要求保存确认，并引导用户到设置删除记忆 | [memory-personalization](../shopping-agent/skills/memory-personalization/SKILL.md) | 同步调整 Agent 行为和前台展示 |

现有长对话处理不是空白：默认在该轮最后一次模型输入达到 100,000 tokens 后，清理较早的大段工具结果。它直接修改工作消息，用简短占位内容替换结果，不自动摘要用户和助手的聊天文字，也不保证下一次调用一定处于上下文预算内。

| 位置 | 职责 |
|---|---|
| `examples/web-shared/` | 匿名身份恢复、访问凭证传递、对话切换、历史加载、流式展示和共享中文文案 |
| `examples/assistant/storefront-web/` | 中文体验页面、历史入口、商品展示、生成素材接入 |
| `examples/demo_common/` | 请求身份校验、对话归属检查、回合生命周期、历史与状态持久化 |
| `commerce_common` 的记忆及上下文模块 | 事实校验、提取和召回规则、工作上下文整理及存储契约 |
| `shopping_agent` 与运行时 | 工具执行、来源校验、卡片补全及每轮上下文装配 |
| `StorefrontBackend` 的部署实现 | 商品来源、购物车和其他购物业务状态 |

Supabase 的配置和具体接入放在部署侧。核心 Agent 继续依赖存储及业务接口。异步请求路径不直接执行阻塞的远程存储调用。

静态提示词和工具定义在同一部署的各轮保持一致。请求级身份、记忆和任务数据沿用现有围栏与缓存断点约定。商品写入、卡片校验和数量限制继续遵循 [安全机制](safety.md) 与 [后端接口](backends.md)。

## 数据所有权与保存约定

以下是建议的逻辑记录。物理字段以现有类型展开，不要求新增独立服务。

| 记录 | 主要内容 | 所有者 |
|---|---|---|
| `conversations` | 用户归属、标题、时间、工作上下文、摘要、任务状态、商品来源状态和版本 | 会话宿主 |
| `turns` | 对话归属、请求去重标识、顺序、本轮原始消息、最终展示片段、完成状态及记忆处理进度 | 回合宿主 |
| `memory_facts` | 用户归属、主题键、事实值、分类、来源回合、来源顺序和更新时间 | 记忆模块 |
| 用户记忆版本记录 | 清空版本及记忆更新所需的来源顺序 | 记忆存储 |
| 购物车记录 | 对话归属、商品行和版本 | 购物业务后端 |

`memory_facts` 以用户与主题键唯一。来源顺序由服务端确定，用于拒绝较旧任务覆盖较新事实。请求去重标识在同一对话中唯一，相同标识携带不同输入时拒绝执行。

### 完整历史

`turns` 只追加本轮新增的原始消息和工具记录，不在每轮重复保存全部历史。最终文字和经过服务端补全的卡片以展示片段保存，保留顺序和必要的结构版本。

原始消息在压缩前归档。不能把已清理的工作消息当作唯一原始历史。前端读取展示片段，不直接展示模型协议内部字段。

打开旧对话不重新运行模型、检索或购物车操作。历史卡片保存当时的商品信息；用户继续操作商品时重新查询当前价格、规格和库存。

### 工作上下文

工作上下文是当前调用所需的信息集合，可以由历史整理生成并保存最新快照。它可以被清理或替换，完整历史不随之改写。

任务条件、候选商品、待解决问题和 `seen_products` 随对话恢复。商品来源状态继续由代码维护，摘要不能替代来源校验或授予写入权限。

### 回合提交

用户输入先可靠记录，再开始模型调用。已完成回合的新增消息、最终展示片段、完成状态和工作上下文版本提交成功后，再向客户端发送完成事件。

同一对话的生成回合避免并发覆盖；其他写入采用版本检查。不能沿用发生冲突后直接让旧回合强行覆盖新状态的策略。已执行的业务动作保留实际结果，不因回合重试自动再执行。

## 对外接口约定

前端使用匿名访问凭证请求 FastAPI，业务数据统一通过 FastAPI 读写。

| 操作 | 建议接口 | 约定 |
|---|---|---|
| 创建对话 | `POST /api/conversations` | 归属当前匿名用户；创建空工作上下文 |
| 列出对话 | `GET /api/conversations` | 只返回当前用户的元数据，支持分页 |
| 读取历史 | `GET /api/conversations/{id}/turns` | 校验归属，分页返回展示片段和回合状态 |
| 发送消息 | `POST /api/chat` | 沿用流式事件协议，增加请求去重标识 |

现有 `X-Session-Id` 可以继续选择对话，并映射到运行时的 `session_id`。每次个人数据请求仍需验证访问凭证和归属。公开入口停止接受任意 `user_id` 作为身份，旧演示会话入口不能绕过此检查。

“新建对话”只新增记录，不调用当前会删除旧会话的 `reset`。现有删除和清空操作与创建对话分开，不把它们绑定到页面刷新或身份恢复失败。

## 短期上下文与长对话

每轮模型输入由固定规则、相关长期记忆、当前任务状态、较早历史摘要及近期完整回合组成。近期回合保留完整的工具调用与结果配对。

调用前按实际模型能力配置上下文预算，为工具定义、动态上下文和模型输出留出空间。中文内容不能仅按英文单词数估算。达到预算时，整理较早已完成的回合，记录摘要覆盖到哪个回合，避免重复摘要或重复注入。

摘要成功后再替换旧摘要和工作快照。摘要失败时保留已有记录，尝试以当前任务状态和完整近期回合构造输入；仍无法满足预算时返回可重试错误，不发送明显超限的请求。原始历史始终可用于重新整理。

当前任务归属对话。一次购物的预算、日期、收礼对象和候选商品不会默认成为跨对话偏好。现有把任务存入单个长期 `current_project` 的自动提取规则需要调整。

## 长期记忆

复用 `MemoryStore`、`MemoryRuntime` 和事实校验。存储稳定偏好、长期约束和明确的持续背景；商品资料、助手推测以及他人的偏好不能自动成为用户本人的事实。当前明确请求优先于旧偏好。

每个完成回合记录记忆处理进度。后台提取可重试，并在同一用户范围内按来源顺序更新。进度记录与回合关联，首期不引入独立任务队列服务。

读取跨对话记忆前，可以在配置的有限等待时间内处理该用户的前序任务。提取超时或失败时，聊天继续使用已保存事实，后台记录失败并重试。回复结束不等于新偏好已经落库；新偏好在提取成功前可能暂时没有生效。前台不为此显示记忆状态。

清空版本检查与事实写入在存储侧形成原子操作。旧任务不能在清空后写回，也不能通过重试绕过版本检查。更正和删除同样需要防止较旧来源重新覆盖或恢复已删除事实。

用户主动要求更正或忘记时，操作限定在当前用户。忘记使用真实删除，不能用覆盖写入冒充删除。记忆技能不再要求普通购物过程中的保存确认，也不引导用户进入不存在的记忆面板。

## 中文内容与商品素材

中文覆盖页面文案、输入提示、错误信息、工具进度文案、商品详情、政策、Agent 回复和卡片字段。内部工具名、商品 ID、分类 ID 和协议枚举保持稳定，通过中文标签呈现。

商品、政策和记忆召回分别验证中文输入。商品检索补充中文分词或关键词匹配及必要别名，保留价格、分类、规格等结构化筛选。首期不以独立向量数据库作为前置条件。

素材流程为：场景设计、结构化数据生成、校验、按商品属性生成图片、资产固化。场景内包含不同价位、规格、配件、缺货替代和无法同时满足所有条件的商品。

详情覆盖尺寸、材质、容量、兼容性、适用条件、维护要求及限制。参与推荐的字段须能通过搜索或详情工具读取。生成的评价和价格记录需要相互一致，避免仅有图表而没有可核对的模拟数据。

图片统一背景、光线、构图和比例。同一商品的颜色变体保持形态一致，图片与数据属性对应。生成图片单独记录来源，不将其标注为已有 CC0 照片来源。文件放静态目录或对象存储，数据库保存引用。

## 建议默认值与范围

以下是可调整的实施默认值，不是额外的已确认产品需求。

| 项目 | 默认建议 |
|---|---|
| 商品规模 | 先补齐现有 87 个主商品的中文详情和主图，再按场景补缺 |
| 商品存储 | 使用可版本化 JSON 和静态图片；需要在线维护时再迁入商品表 |
| 币种 | 沿用现有 USD 定价，使用中文格式；人民币重新定价另行处理 |
| 新用户内容 | 空历史、空记忆，不继承 `demo-user` 的预置偏好 |
| 数据保留 | 不启用自动删除；新建对话和清除浏览器标识均不清理云端记录 |
| 上下文参数 | 阈值、预算和近期回合范围配置化，通过实际模型和长对话验证调整 |
| 后台参数 | 提取等待时间、重试次数和退避配置化，失败可观察 |
| 首次部署 | 单个 API worker，沿用现有进程内工具锁的运行边界 |

本次不建设账号管理、跨设备身份恢复、真实支付或完整电商管理后台。多 worker 或多实例扩展需要另外验证工具锁、任务领取和写入串行化。

## 部署与迁移

统一 HTTPS 域名承载页面和 `/api`。前端使用生产构建，API 地址不再指向访问者自己的 `localhost`。允许域名和代理转发按实际部署配置。

反向代理支持 SSE，关闭会阻止及时输出的缓冲和缓存，并设置适合流式请求的连接超时。部署时验证聊天模型和记忆模型均可调用，不能只以健康检查通过作为 Agent 可用的依据。

业务表启用行级访问限制，前端不直接访问内部业务记录。服务端凭证不进入浏览器、模型上下文或日志。服务凭证绕过数据库 RLS 时，后端仍强制执行用户归属检查，不能把 RLS 当作已经完成的隔离。

公网入口对匿名身份创建和模型调用设置基本频率、并发与额度限制。具体数值依据部署容量配置，不扩展为独立权限系统。

数据库不可用时，不回退到共享演示用户，也不宣称历史已保存。断流时保留已提交内容；服务重启后，无法继续的进行中回合标为中断，重试不自动重放业务写入。

现有本地记忆文件保留，不自动映射到新匿名用户。旧进程内历史无法凭空恢复。数据库变更以明确的迁移建立新存储，不能在启动时清空用户记录或反复灌入预置记忆。

实施接入需要落实服务器或平台、域名、Supabase 项目和模型服务配置。它们是部署条件，不改变上述产品行为。

## 测试契约

### 功能正确性

- 中文商品和政策检索命中正确内容，价格、分类、规格和库存条件有效。
- 匿名身份创建与恢复、会话创建、列表分页、历史读取符合接口约定。
- 事实更新、删除和清空作用于正确用户，来源和版本信息可追溯。
- 上下文整理保持近期完整回合和当前任务条件，不改写完整历史。
- 生成数据通过现有模型校验，商品与变体引用有效，图片引用可读取。

### 功能交互

- 同一用户的新对话读取长期偏好，不继承另一对话的临时任务或购物车。
- 恢复历史时还原文字和最终卡片，不重新调用模型或执行工具。
- 恢复旧对话后，来源校验、购物车状态和后续操作保持一致。
- 当前要求覆盖冲突的旧偏好，代他人购买不污染用户本人的长期偏好。
- 记忆提取失败不阻断普通聊天，成功重试后后续请求能读取结果。
- 前台不出现记忆面板、计数、读写进度或普通购物中的保存确认。

### 边界条件

- 用户 A 即使知道用户 B 的对话 ID，也不能读取历史、记忆或修改购物车。
- 页面重复挂载、多标签页初始化和网络失败不错误创建新身份。
- 重复请求不重复生成或写入；同一请求标识配不同输入被拒绝。
- 同一对话发生并发写入时拒绝过期版本，不丢失较新的操作。
- 清空或删除与后台提取交错时，旧任务不能恢复被删除的信息。
- 长对话、超大工具结果、摘要失败和预算不足均有明确处理。
- 流式连接中断、数据库写入失败和服务重启不伪造完成状态。

沿用现有会话冲突、记忆清空、工具来源和流式协议测试作为回归基础。单元和集成测试使用可控的身份、存储和模型替身；真实模型行为另用体验场景验证。

## 验收证据与实施顺序

浏览器验收使用普通窗口和无痕窗口作为两个独立身份，并用同一浏览器的多个标签页验证身份复用。验收覆盖域名访问、中文流式回复、历史与卡片恢复、新对话个性化、用户隔离以及服务重启后的恢复。

长期记忆的验收先通过开发侧记录确认提取成功，再验证新对话的推荐结果。另行注入提取延迟和失败，验证等待及重试行为；用户界面不承担记忆调试功能。

实施顺序：

1. 建立匿名身份和用户归属边界，接入持久化存储与数据库迁移。
2. 完成回合保存、请求去重、历史列表、卡片恢复和购物车状态恢复。
3. 完成长对话预算、工作上下文摘要和可靠的后台记忆处理。
4. 完成中文界面与检索，生成、校验并接入商品数据和图片，移除记忆展示及相关话术。
5. 配置域名与流式代理，运行仓库检查、Web 构建和真实部署体验验证。

实现验证使用仓库约定的 `ruff check .`、`ruff format --check .`、`pytest` 和 `python scripts/verify_all.py`。真实域名验收补充验证匿名身份、数据库、两个模型及流式代理的连接，不以离线测试代替部署验证。
