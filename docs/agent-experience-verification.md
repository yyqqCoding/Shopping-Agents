# 户外体验站实现与验证

实现遵循 [体验站设计](agent-experience-design.md)。当前代码提供动画首页、户外聊天界面、96 款人民币装备、匿名历史与长期记忆，以及旧目录兼容。本次按用户要求不新增或修改测试文件及测试脚本；验证使用已有检查、生产构建和浏览器操作。

用户已确认原版本的域名服务可以使用。户外版本尚未部署，`002_outdoor_cart_currency.sql` 尚未在真实数据库执行；本地结果不代表线上迁移与模型推荐已经验收。

## 行为覆盖

| 需求 | 实现与证据 | 边界 |
|---|---|---|
| 动画首页 | `/` 使用原创 SVG 山野场景，点击进入 `/chat`；浏览器确认首页没有身份或 API 请求，减少动态效果设置生效 | 不生成商品照片 |
| 历史与购物车布局 | 左侧历史栏可折叠并保存状态；手机历史弹窗、右下角圆形购物车与右侧抽屉可操作；Escape、遮罩关闭和焦点返回有效 | 使用本地身份与 API 夹具 |
| 字体与响应式布局 | 正文、卡片和控件放大，宽聊天区；320、390、768、1440 px 视口没有页面横向溢出，输入框按宽度和内容调整高度，购物车按钮避开输入框 | 手机检查为 Chrome 设备模拟 |
| 户外商品与推荐依据 | 8 类、96 个主商品、120 个尺码变体；规格、限制、模拟评价与价格固化；中文帐篷检索、重量、容量、舒适温度筛选经离线调用核对 | 真实模型的选型与追问效果需线上体验 |
| 人民币与旧目录 | 新商品、卡片和购物车使用 CNY；旧商品不参与搜索；浏览器确认旧购物车仍显示 US$149.00，数量和结算禁用，移除与查看保留 | `002` 的真实事务执行待验证 |
| 金额与配送 | 对比不计算跨币种差价，计划注明每步一件的参考口径；匹配当前购物车时配送使用实际数量，229 元的两件商品按 458 元判断免运费 | 结算不下单、不扣款 |
| 匿名身份与历史 | 保留身份键，`outdoor-v1` 仅区分选中的对话；旧历史仍可访问，当前户外入口首次创建空对话；历史和最终卡片可恢复 | 真实多访客隔离、重启恢复待部署验收 |
| 短期与长期记忆 | 沿用工作上下文预算、完整历史归档、按用户保存偏好及后台重试；户外提示词静默使用相关偏好，临时行程留在对话内 | 本次未调用真实聊天、摘要或记忆模型 |

21 个 Python 失败项依赖旧 ACME 名称、`AR-` 在售商品、旧分类、会员与配送规则或订单工具。一个会话隔离用例也在加入已下架的旧商品时停止。新目录明确替换这些行为，本次不修改测试来适配；不能将全量 `pytest`、统一验证命令或 CI 记为通过。

现有 `browser-smoke.mjs` 依赖旧首页和固定购物车布局，`smoke_chat.py` 保留旧购物场景，均未改写为户外验收脚本。浏览器操作使用实际生产页面与本地夹具，验证页面行为，不连接 Supabase 或真实模型。

Python 检查使用已有 Windows Python 3.11，Node 检查使用 Linux Node 22.21.1。现有依赖包含 Windows 原生模块，Web 在隔离目录使用 Windows Node 20.17.0 和 `NODE_OPTIONS=--max-old-space-size=768` 构建；原开发目录的 `.next` 保留。部署镜像仍使用 Node 22，需要在服务器完成 Docker 构建。

## 部署验收

按 [户外版本升级](deployment.md#户外版本升级) 拉取代码并构建镜像，停止 API 后执行 `002`，再启动新版本。已有项目不重复执行 `001`，不重置数据库；商品 JSON 随源码更新。

真实环境还需确认 CNY 新购物车、USD 旧购物车、旧历史恢复，以及 [部署验收](deployment.md#部署验收) 中的匿名隔离、长期偏好、长对话、断流和重启恢复。沿用线上 Supabase 项目时，不同时启动本地和线上 API。数据库事务检查只能使用 [独立测试项目](../supabase/README.md#transaction-verification)。
