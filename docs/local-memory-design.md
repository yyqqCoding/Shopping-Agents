# 本地会话与记忆设计

## 范围与决定

会话与记忆采用本地文件存储。原始对话使用 JSONL，会话笔记和长期记忆使用 Markdown，大工具结果使用独立文件，机器状态使用 JSON。格式职责参考本地 `claude code/Claude-Code`，不强制所有内容使用 Markdown。

不导入旧 PostgreSQL 会话、记忆和匿名身份。新系统从空数据目录开始。切换不自动删除远端数据库；删除旧基础设施属于独立运维操作。

匿名身份也迁到本地。浏览器持有随机访问凭证，服务端验证凭证并确定用户，移除应用运行时的 Supabase Auth 与 PostgreSQL 依赖。用户 ID、会话 ID 和磁盘路径不作为访问凭证。

本阶段先实现本地持久化和短期记忆八项机制。长期记忆改为本地 Markdown，保留现有读写、编辑、删除能力；完整长期记忆迁移见 [本地长期记忆完整迁移设计](long-term-memory-design.md)，团队记忆已明确排除。前端改动限于本地身份协议和必要的压缩状态展示，前端整体性能优化另行实施。

商品目录、库存、购物车与订单继续由 commerce service 提供。其 MySQL 不属于本次移除范围。JSON 演示后端需要检查购物车与幂等记录的持久化，不能再隐式依赖 Supabase。

## 文件布局

数据根目录由 `SHOPPING_DATA_DIR` 指定，不位于静态资源目录，不进入 Git 或容器镜像。一个数据目录只允许一个 API 写入进程；启动时取得进程级独占锁，第二个写入进程必须拒绝启动。

```text
data-root/
  schema.json
  writer.lock
  identities/
    <credential-digest>.json
  usage/
    <day>.jsonl
  users/
    <user-id>/
      memory/
        MEMORY.md
        <fact-id>.md
        state.json
      conversations/
        <conversation-id>/
          transcript.jsonl
          events.jsonl
          checkpoint.json
          session-memory/
            revisions/
              <revision>.md
            summary.md
          tool-results/
            <result-id>.txt
```

`transcript.jsonl` 是原始消息归档，消息 ID 稳定，记录角色、内容、所属回合、时间和工具关联。`events.jsonl` 记录回合开始、已确认展示、结束、压缩边界、状态提交与后台任务状态，支持恢复和幂等重放。实现时避免同一事实有两个互相竞争的权威来源：事件日志是提交依据，checkpoint 是可重建的读取快照。

`checkpoint.json` 保存工作消息引用、会话版本、provenance、待注入应用事件、运行中回合、摘要版本与 token 基线。原始 transcript 不受工作上下文压缩修改。

`summary.md` 是当前笔记的可读副本；checkpoint 或笔记提交事件引用不可变的 `revisions/<revision>.md`，不能依靠两个文件同时原子替换。机器维护的覆盖边界与版本不交给模型编辑。

长期记忆每条事实使用 Markdown 正文和必要 frontmatter，`MEMORY.md` 是索引。`state.json` 保存删除代次、来源顺序及删除记录，避免后台旧任务恢复已删除内容。索引可从事实文件重建。

## 本地身份与访问边界

服务端生成至少 256 bit 随机不透明凭证。浏览器只通过同源身份接口获得凭证并在请求中携带；服务端持久化摘要及其绑定的用户 ID，不持久化明文凭证。访问凭证不进入 URL、日志或文件名。

新浏览器创建匿名身份；已有凭证验证失败时提示恢复失败，不静默创建新用户掩盖身份丢失。多标签页继续使用 Web Locks 协调创建。采用新的浏览器存储键，旧 Supabase 凭证不参与新协议。

创建身份接口有速率和资源限制。所有会话、记忆、历史及工具结果接口均由验证后的用户定位资源。客户端不能提交用户 ID 来决定访问范围，模型不能传入任意磁盘路径。浏览器遗失凭证即无法找回原匿名身份，此限制保持可见。

## 八项短期记忆机制

### 1. 完整历史留档

每条原始消息以稳定 ID 写入 JSONL。工作上下文与归档分离，压缩不改写原消息。回合开始先提交请求 ID 与用户消息，完成后提交模型消息、工具结果、展示记录及状态。

同一请求 ID、相同输入返回原回合；相同 ID、不同输入拒绝。恢复不能重新执行已经开始的业务写入。异常中断的回合标记 interrupted，下一轮重新查询业务状态后继续。

历史读取按回合分页。模型回查按消息 ID、工具结果 ID 或关键词限定范围，返回带来源的原文和明确截断信息，禁止一次重新读回全量历史。

### 2. 大工具结果外置

对新工具结果执行单结果大小和同轮聚合预算检查。超过预算的适用文本结果原文落盘，进入工作上下文的是稳定预览及不透明资源 ID。原始归档保留完整来源或其持久化引用。

同轮聚合预算沿用参考实现的每条工具结果消息 200,000 字符，单结果继续使用本项目的 12,000 字符阈值。先处理超出单结果阈值的正文，再按剩余正文大小从大到小外置，直到适用结果的总量（包含预览及引用）不超过聚合预算，或已无可缩小的结果。预览最多保留 2,000 字符。同一轮按模型调用顺序保存结果，外置选择不改变工具配对或前端事件顺序；只处理新结果，不重新改写历史替换文本。

归档读取、记忆文件读取和技能加载不再次外置，避免读取文件后又被替换为同一个文件引用。业务写入确认、错误及拒绝结果保留原文，不参与可外置结果预算；它们仍计入完整上下文窗口预算。落盘失败保留原文并继续处理其他结果，不生成失效引用，也不重试已经执行的业务工具。没有持久化回调的宿主保持原有行为。

写文件失败不能产生不可读引用。已发送的替换文本保持稳定，避免每轮改变缓存前缀。结构化写操作确认、关键错误、provenance 和当前必要条件不能被随意清掉。

增加有大小限制的结果读取能力，服务端从当前用户和会话解析资源 ID。不能向模型暴露拥有任意文件读取权限的接口。

### 3. 轻量清理旧工具结果

按工具调用 ID 识别可清理结果，保留近期结果及完整 tool_use/tool_result 配对。仅替换旧结果正文，保留结果引用和清理说明。

参考源码的时间触发默认参数为禁用、间隔 60 分钟、保留最近 5 个可清理结果。参数可配置。60 分钟代表其缓存假设，不直接宣称适用于当前网关。服务端 cache editing 单独能力开关控制；未验证前不发送相关字段。

旧的回合结束后按 100k tokens 一次清理到一半的机制应被新流程替代，避免两套清理互相干扰。

### 4. 后台维护 SessionMemory

按参考源码的初始参数工作：上下文达到 10k tokens 后初始化；相对上次笔记增长至少 5k tokens，再结合 3 次工具调用或助手自然停顿触发。参数可配置，不增加独立的“是否需要记忆”模型判断请求。

后台任务使用固定对话快照和当前笔记，串行更新同一会话。笔记保留固定结构：任务要求、当前状态、关键资料、用户纠正、候选与决策、关键结果、已完成操作、未完成任务。保留具体条件和原因，不以极短摘要替代详细交接。

模型仅能提交笔记更新，不能读写其他用户文件或直接修改覆盖边界。采用隔离请求上下文；在网关支持时复用主对话请求前缀与模型缓存。后台调用仍然计费，不承诺比临时摘要更便宜。

任务在停止服务时可取消；未成功提交的任务不推进覆盖边界。下次启动或后续触发可重新生成，不能重复业务工具写入。

### 5. 精确记录覆盖边界

笔记提交包含 conversation_id、revision、source_revision、covered_through_message_id 和内容摘要。来源边界必须存在于当前会话，任务结果只能覆盖其启动时已观察到的历史。

模型生成期间新增的消息继续保留。旧任务不得覆盖更高覆盖边界或更新版本的笔记。仅在完整工具调用/结果边界推进覆盖位置。

### 6. 优先使用已有笔记压缩

达到自动压缩阈值时，优先尝试已提交笔记。正在提取时允许有上限等待，参考实现为 15 秒；超时或失败后进入回退路径。

从笔记覆盖边界之后保留未覆盖消息，按参考规则向前扩展近期原文。参考默认值为至少 10k tokens、至少 5 条含文本块的消息、向前扩展预算约 40k tokens。这里的消息数不是用户回合数，40k 也不能用来静默删除未覆盖消息。

调整保留边界以保护工具配对和同一模型消息的相关内容块。剔除会引起重复裁切的旧压缩边界。构建后的完整请求再次检查预算；笔记为空、边界缺失或仍然超限时不提交本次压缩。

### 7. 完整摘要回退

笔记路径不可用时，使用主模型生成详细交接摘要，覆盖用户请求、条件变化、纠正、已完成操作、当前工作、待办及下一步。尽量复用相同静态提示、工具定义和对话前缀的缓存；失败时使用独立流式摘要请求。

摘要调用不能执行购物或订单工具。空内容、API 错误和取消不作为成功摘要。请求过长的恢复按完整协议消息组有限裁剪，并记录这一降级，不能伪装成无损压缩。

采用有限重试和连续失败熔断，参考自动压缩失败阈值为 3 次。熔断后禁止发送已知超窗口请求；向用户提供可继续处理的错误，同时保留记录。

普通完整压缩与 SessionMemory 压缩分别实现：不能假设普通完整压缩必然保留最后四轮原话。

### 8. 恢复必要状态

重建顺序遵循参考实现：边界、摘要、该路径保留的消息、必要资料、恢复结果。购物场景恢复当前任务、必要商品证据、已加载技能及工具能力信息；价格、库存、购物车通过业务接口重新确认。

provenance、写入权限和幂等记录来自服务器状态，不从摘要授予。摘要携带可回查的会话资源引用，模型继续最新任务而不重复已经完成的动作。

## token 与模型能力

窗口值显式配置，不能根据代理模型别名猜测。基线采用最近一次有效 API usage，加上未覆盖消息估算；模型、系统提示、工具定义和压缩视图变化时使不再适用的基线失效。

必须用真实 API 核对 input_tokens、cache_read_input_tokens、cache_creation_input_tokens 是否互斥，以及输出和 thinking 的计费及窗口占用口径。缺字段使用明确标记的保守估计，不把缺失缓存指标解释为缓存命中。

参考自动压缩公式是窗口减输出预留，再减 13k 缓冲；输出预留为模型最大输出与 20k 的较小者。对小窗口必须校验参数有效性，不能产生负预算。笔记阈值、保留范围和摘要预算应一起验证。

缓存复用是性能能力，不是正确性前提。网关不支持时退回普通摘要请求，不依赖未实现的缓存编辑 API。

## 写入、恢复与部署

磁盘操作离开事件循环执行。进程级独占锁、进程内状态锁与会话锁承担不同职责：前者禁止多写入进程，状态锁保护提交，事务期间不得等待模型请求。

JSONL 提交写入后 flush/fsync；快照和 Markdown 使用同目录临时文件加原子替换。启动时只允许处理日志末尾未完成的记录，日志中部损坏应报错，不能跳过后继续使用不完整状态。

跨文件提交先保存不可变内容，再写提交事件，最后更新可重建快照。恢复以提交记录为准，孤立文件不能自动视为已完成任务。业务写入与本地提交无法形成跨系统事务，因此保留 commerce service 操作 ID，未知结果先查询确认，不自动重放。

数据目录挂载持久化卷。容器替换、应用更新不清空卷。数据及凭证摘要不进入日志、静态服务或镜像；备份按整个数据目录进行。初版不支持多个 API 副本同时挂载写入。

## 模块与改造顺序

1. 本地文件提交、身份验证、会话存储、长期记忆 Markdown 适配及部署卷；替换 Supabase 运行时依赖。
2. 原始消息 ID、工具结果外置和受控回查工具。
3. 统一预算和请求前轻量清理。
4. SessionMemory 后台任务、覆盖边界和版本提交。
5. 笔记压缩、完整摘要回退、状态恢复与日志指标。

共享机制放在 `commerce_common`，API 的身份、目录布局和会话所有权放在 `demo_common`。新增模块同步更新根 `AGENTS.md` 与所属 README。前端保持现有历史和记忆管理交互，身份接口改为同源本地接口。

## 验证约定

按用户要求不新增测试文件，不运行全量自动化测试。执行必要的静态检查和人工运行验证；真实模型探测只覆盖窗口配置、usage 字段语义、缓存和摘要请求兼容性，不通过逐步填满超大上下文反复消耗额度。

人工验证覆盖匿名身份恢复、跨用户访问拒绝、同请求重放、回合中断恢复、工具配对、笔记期间新消息保留、压缩后条件与任务连续性、删除记忆后旧任务不得恢复、容器重启后数据可读。记录测得指标与未验证项，不将静态分析结果描述为线上通过。

记录请求开始、模型开始、首可见内容、工具耗时、笔记耗时、压缩耗时、原始及重建 token 估计、缓存 usage、保存完成。指标不包含凭证或完整用户内容。

## 实施与验证状态

### 短期记忆对齐补齐方案

以本地参考目录 `src/services/SessionMemory/`、`compact/sessionMemoryCompact.ts`、`compact/compact.ts`、`utils/tokens.ts` 为逐项依据，替换此前按回合保留和独立摘要的简化实现。下列内容先作为设计写入，完成状态以补齐后的验证记录为准。

- 使用有效 API 输入与缓存 usage 建立请求基线，并估算响应后新增消息；模型、系统、工具或消息前缀变化后失效。输出 usage 为零但响应非空时单独估算输出，不丢弃有效输入 usage。缺失 usage 保守回退并记录估算来源。缓存输入是否已包含在 input 中由网关配置显式声明。
- SessionMemory 在主模型每轮结束并配齐工具结果后检查，首次上下文达到 10k，此后增长至少 5k，且新增工具调用至少 3 次或当前助手轮没有工具调用。初始化、成功提取时的上下文大小及工具游标持久化；失败不推进成功边界。后台每会话串行，运行期间保留最新尾随快照。
- 原始 JSONL ID 与工作消息维护对应关系；笔记边界必须能在当前工作消息中精确定位。后台快照固定，新增消息继续保留。笔记覆盖可落在一个用户回合内部的完整工具配对边界，不再仅记录回合数。
- 后台笔记继承主请求的模型、system、tools、thinking 和 messages 前缀。使用已有 exact-string 编辑工具 `memory_edit`，分支只允许编辑 `session-memory/summary.md` 的暂存副本，禁止调用购物或其他记忆工具。采用参考模板结构、章节提醒与 12k token 总预算；成功后原子提交内容和覆盖 ID。
- 即将压缩时最多等待运行中的笔记 15 秒；超过 60 秒的旧提取不额外等待。每轮请求前都可消费新笔记，而非只在用户下一轮开始时检查。
- 笔记压缩先保留全部未覆盖消息，再向前扩展到至少 10k 估算 tokens 与至少 5 条含正文消息，扩展达到 40k 时停止。40k 不用于删掉未覆盖的新消息。调整边界保护所有保留工具结果对应的调用及同响应拆分块；剔除旧压缩标记，组装后再次检查完整请求。
- 普通完整压缩独立于笔记保留算法：继承主模型请求前缀生成详细交接，工具全部拒绝执行；失败时使用主模型的独立流式摘要。对于明确超长请求，按 API 轮分组削减约 20% 的头部组（至少一组、至少保留一组）并有限重试，原始 JSONL 不变。摘要为空、工具调用、取消、截断输出均不推进压缩边界。连续失败三次熔断。
- 压缩产物携带原始归档回查说明，动态业务状态、工具和技能能力由宿主继续提供；已读资料给出受控引用供重新读取。输出预留按显式模型最大输出能力与 20k 的较小值计算，和主回复的 `max_tokens` 分离。缓存命中率仍需网关实测，不能用实现完成代替收益验证。

当前体验站的身份、会话、原始归档和个人长期记忆均使用本地文件。短期记忆由 `context.py`、`session_memory.py`、主运行时和本地宿主共同实现：有效 usage 基线、逐模型轮触发、后台 exact-string 笔记编辑、精确覆盖 ID、笔记优先压缩、继承主前缀的完整压缩及独立流式回退均已接通。主提示和工具定义保持稳定，分支仅在隔离的笔记副本上编辑，成功后提交版本与覆盖位置；原始 JSONL 不因工作上下文压缩而改写。

笔记采用参考模板和完整更新提示词，工具名映射为现有的 `memory_edit`；参考的文件编辑权限映射为当前用户会话的 `session-memory/summary.md`，不授予购物或其他记忆写入权限。继承分支保留主模型、max_tokens、system、tools、thinking 和消息前缀；普通压缩禁止执行工具，失败才换用独立流式摘要。格式提醒交由参考提示词处理，不额外增加会使正常编辑失败的模板校验门槛。网关把工具参数返回为 JSON 字符串时统一解析；不可解析的参数只返回工具错误，不执行调用。

源码外部构建缺少可用的服务端缓存编辑实现，本部署不发送未验证的缓存编辑字段。时间触发清理默认关闭，启用后才按空闲间隔清理旧读结果并保留最近结果与调用配对。`SHOPPING_CONTEXT_RECENT_TURNS` 保留配置兼容读取，不再决定裁剪范围。事件日志仍保存压缩快照，磁盘占用随回合增长；这是存储容量管理事项，不改变原始消息和笔记覆盖语义。生产购物车与订单应使用 `java` 后端，`json` 夹具的购物车在进程内存中。
