# 本地长期记忆完整迁移设计

## 范围与约定

本次完整迁移仓库中 `claude code/Claude-Code` 的个人长期记忆机制。保留文件组织、记忆类型、读写规则、相关性选择、异步预取、后台增量提取、缓存复用、Dream 整理、历史回查、管理入口、日记模式、独立 Agent 记忆及快照。实现顺序不代表功能删减或延后交付。

用户已明确不需要团队记忆。团队目录、共享索引、组织身份、团队云同步及其专用扫描与同步界面不在范围内，不保留待接入的团队服务任务。

长期记忆继续使用本地文件，不引入 PostgreSQL、向量数据库、embedding、额外关键词排序或新的记忆算法。原始对话继续使用 JSONL，长期记忆使用 Markdown，任务游标、设置和删除版本使用 JSON。身份、持久卷和短期记忆沿用 [本地会话与记忆设计](local-memory-design.md)。

参考基线是当前本地源码快照，不将还原文件、注释或实验开关视为某个官方发布版本的承诺。本文是编码前的设计，所列目标功能尚未因本文写入而实现。

本次只按用户要求编写设计文档。编码不得早于设计文档落盘；不新增测试文件，验证方式见文末。

## 已核实的源码缺口

`src/skills/bundled/dream.ts` 当前只有空的 `registerDreamSkill()`。自动 Dream 的调度、整理提示词、执行循环和任务状态均有实现，但不能宣称手动 `/dream` 注册也已还原。手动入口应调用已有 `buildConsolidationPrompt`，接入现有主对话执行流程；这一入口补接须单独标注，不能新增另一套整理算法。`recordConsolidation()` 的手动调用语义是构建提示时记时，不伪装成整理成功后提交。

日记提示词提到夜间整理；已核查的日记与 Dream 模块没有完整的夜间调度实现，且自动 Dream 明确跳过日记模式。保留日记模式和已有整理流程，补接日记整理的调用入口与生命周期；不得仅在提示词中声称存在夜间任务，也不得自行宣称某个调度时刻来自源码。日记整理的自动运行时机必须在实现记录中明确标为宿主接线，不能替换普通模式的原自动门槛。

`/remember` 有完整审阅提示词，但注册仅限源码内部用户环境。迁入时保留审阅行为与功能开关，将平台内部身份判断映射为本地部署配置，不能把内部身份字符串当作本项目用户认证。

远程实验配置的实际线上取值不在源码内。迁移保留各能力的独立开关和依赖关系，使用显式本地设置代替远程实验服务；源码回退值与部署实际启用值分别记录。不得以缺少实验服务为由交付永远无法启用的空分支。

## 当前项目需要替换的链路

`examples/demo_common/local_persistence.py` 的 `LocalMemoryStore` 已把事实写入 Markdown，但 `get_facts()` 仍读取全部事实，`search_facts()` 仍全量读取后关键词匹配；现有 `MEMORY.md` 只有 key 与文件链接，没有用于判断相关性的描述，也没有接入模型读取链路。

`commerce_common/memory.py` 的 `tier_one()` 先读取全部事实，再选择约束和近期事实。`extract_and_store()` 把全部已有事实与本轮文本交给独立提取请求；值长度与三类 `MemoryCategory` 约束仍沿用旧事实模型。

迁移后，Markdown 主题记忆及其索引成为个人长期记忆的内容来源。现有全量事实选择、关键词召回、三类事实提取不再与新链路同时运行。记忆管理列表可以分页列出文件元信息，但不能因此在每次模型请求前读取全部正文。业务系统的用户资料、购物车、订单与价格库存仍通过业务接口查询。

`state.json` 只保存删除代次、来源顺序、索引/文件版本及任务边界等机器元数据，不再复制长期记忆正文。设置、任务游标和原子提交接入已有本地存储，避免同一内容产生两个权威版本。旧 Supabase 数据不导入；本地旧事实格式只在确实存在时转换为主题记忆，保留删除信息，不恢复已删除项。

文件采用源码可读的主题命名与 Markdown frontmatter：

```markdown

name: 用户本人鞋码
```

```markdown

```

## 记忆规则与即时操作

完整迁入四类定义、保存时机、用途、排除项、读取时机和新鲜度规则。购物领域示例替换代码领域示例，分类和处理流程保持一致。

长期有效的本人尺码、偏好和用户明确给出的协作反馈可以保存。临时任务进度进入 SessionMemory；商品实时价格、库存、购物车和订单状态从业务系统读取。用户最新陈述优先于旧记忆，给其他人购买不能套用用户本人尺码。相对日期保存为绝对日期。

用户要求记住时立即保存，纠正时更新原主题，忘记时删除相关记忆及索引引用。用户要求忽略记忆时，当前请求不得读取、应用、比较或提及被忽略的记忆。记忆内容不授予购物写入权限。

迁入记忆文件的读取、搜索、列举、写入和编辑能力。编辑要求先读取同一文件，避免覆盖未见内容；读取版本发生变化时重新读取。文件变化通知与读缓存失效一起迁入。后台任务只获得原源码允许的只读操作及记忆目录写入权限，不能执行购物写入、订单提交、外部工具或任意 shell 写入。

Web 服务的文件访问限制为当前用户允许的记忆、指令层和归档资源；源码单用户 CLI 中的全文件系统读取权限不能变成匿名 Web 用户的服务器文件读取权限。这是宿主隔离接线，不改变记忆选择和整理算法。

## 两种召回模式

### 索引模式

将受限 `MEMORY.md` 放入每次主对话的动态上下文，主模型根据索引按需读取或搜索主题文件。固定的行为规则进入静态提示词，用户索引、正文和时间等动态数据放在缓存断点之后，遵守仓库的提示词装配规则。

索引仅包含短链接与一句相关性描述，不放整段记忆正文。超限时按源码逻辑截断并给出可见的截断信息；文件仍可按需读取。不能用截断掩盖未维护的索引。

### 自动选择与预取模式

启用该模式时跳过常规自动记忆索引注入，按源码关系切换，避免把两种模式叠加。

读取各 Markdown 的前部元信息，排除 `MEMORY.md`，按修改时间降序截取候选。选择模型接收用户当前问题、候选清单和近期成功使用的工具，输出结构化文件名列表。优先选择明确有用的文件，允许返回空列表，校验返回项确实来自候选。

选择请求按独立 side query 执行。模型选择角色独立配置，对应源码的默认 Sonnet 角色；不强制使用更便宜模型，不改为关键词或向量评分。输出使用源码的 JSON schema 契约，网关是否支持在真实能力验证中确认。

预取与主模型生成、工具执行并行。只在源码规定的工具后收集点消费已就绪结果；未就绪则留到下一次迭代，不能为预取无条件阻塞首个主模型请求，也不能保证没有后续迭代的简短回答必定用上预取。主模型显式回忆仍走按需读取路径。

已有上下文中已注入的路径和模型主动读取的文件参与去重；不占用候选选择名额重复推荐。压缩删除旧注入内容后，从现存上下文重新计算去重集和累计预算，允许重新召回。请求结束或取消时中止未完成预取。

源码用“输入包含空白”排除单词式请求，会同时排除无空格中文句子。中文宿主需按同一“有效问题长度”意图接线，确保正常中文请求进入原选择器；这一语言适配须记录，不能偷偷替换为新的召回算法。

## 后台增量提取

完整回复自然结束时检查提取开关，只针对主对话触发。每个会话持有上次已处理消息 ID、是否运行、累计合格回合数和待处理最新快照。只有成功结束才推进提取游标；原游标因工作上下文压缩不存在时，按源码回退为当前全部可见消息。

提取提示词强调只从游标之后的新消息提取；分支为缓存复用仍继承主对话前缀，不得把“只提取新消息”误写成“API 请求只包含新消息”。主模型在该范围已经写过记忆时跳过后台分支并推进范围，避免重复。

分支开始前注入文件头清单，先并行读取可能更新的文件，再并行写入或编辑。写入前检查已有主题，保留没有新记忆时不写文件的行为。后台调用最多 5 轮，不能执行额外调查、重复业务操作或无限验证。

同一会话串行执行。运行中到达的新任务覆盖待处理快照，当前任务结束后运行尾随提取；尾随任务按新的游标计算范围，跳过普通回合节流。失败保留游标，后续可重新考虑该范围；退出时有上限等待，不把后台分支记录混入主对话 transcript。

当前本地记忆作业的持久化与删除代次继续承担恢复和防止旧写入覆盖新纠正的职责。新的分支结果必须经过该提交检查，不能因完整搬迁而让旧任务恢复已删除记忆。

## 缓存与调用口径

提取和自动 Dream 使用同一分支执行基础设施。继承主请求的静态提示词、动态前缀、工具定义、模型、消息前缀和 thinking 配置；工具权限通过执行检查限制，不通过每次更换工具列表破坏缓存键。

背景任务是实际模型请求，仍然计费。既不承诺比旧提取便宜，也不把分支缓存命中作为正确性条件。输出上限可能影响 thinking budget，应保留源码的配置关系，不能为节省输出随意修改并宣称共享缓存。

当前网关曾出现流式可见输出但 `output_tokens=0`。缺失或异常 usage 标明不可用，不能记为真实零成本。上下文预算沿用现有保守方法，真实模型验证分别记录普通输入、缓存创建、缓存读取、输出、模型角色和请求耗时。

## Dream 整理与任务生命周期

自动 Dream 在完整回复结束处检查开关、模式、时间、扫描节流和会话门槛。会话数量指上次整理之后有修改的会话，排除当前会话，不改为消息数或用户登录次数。

执行原四阶段流程：了解目录与索引、收集近期信号、合并更新主题、清理维护索引。只定向搜索有明确线索的 JSONL，不完整读取所有 transcript。优先更新已有主题、转换相对日期、纠正冲突及过时事实。

整理锁使用源码的上次整理时间、持有者及过期语义；失败或取消回退到之前的整理时间，取消不回滚已经实际完成的文件编辑。成功保留本次时间。保留失效持有者回收及扫描节流。

任务状态包括运行、完成、失败和取消；阶段在首次观察到写入时从 `starting` 转为 `updating`。展示近期助手文本、工具数量、涉及文件和可取消入口。文件清单只表示观察到的写入，不冒充完整审计清单。完成有更新通知；空整理明确报告无变更。

手动 Dream 使用同一整理提示词，在主对话权限与执行循环内运行，不强行套用自动整理的时间/会话门槛。手动入口缺失的补接单独记录，不新增一套整理策略。

## 日记模式

完整保留 `logs/YYYY/MM/YYYY-MM-DD.md` 模式：使用上下文当前日期，跨日切换文件，每条记录为简短带时间的追加项，不重写和重排已有日记。保存类型与排除规则和普通模式一致。

该模式下主模型只追加日记，不直接维护整理后的索引；已有 `MEMORY.md` 和主题文件由整理流程维护。日记模式保留自动选择开关对索引加载的影响，不与普通自动 Dream 强行同时开启。

日记的整理入口使用已有整理提示词中的日志优先路径。定时调度接线的源码缺口依前述规则明确标注；不能把日记仅落盘、整理永不触发当作功能完成。

## 独立 Agent 记忆与快照

保留 `user / project / local` 三个作用域、Agent 类型目录、独立 `MEMORY.md` 和作用域提示词。Agent 被点名时按源码选择其记忆目录；普通对话使用个人自动记忆目录。

保留快照存在与版本检查。没有本地记忆时从快照初始化；已有本地记忆而快照更新时提供采用更新或保留本地的选择。替换时清理原 Markdown，复制快照并更新同步时间；选择保留时只记录已处理快照版本。快照不涉及团队云同步。

当前购物 runtime 没有完整的通用 AgentTool 调用面。迁移提供独立 Agent 的记忆上下文、目录路由和快照管理接口，不以这次工作另建通用多智能体编排产品；不得把没有任何可调用入口的文件视为该能力完成。

## 管理、审阅与指令层

Web 记忆管理承接原 `/memory` 功能：列出索引与主题文件、查看编辑、总开关和自动 Dream 设置。编辑后使相关读取状态与缓存失效。保存/改善记忆的通知显示实际涉及的文件，可打开查看。

原 `/remember` 是分层审阅：收集允许访问的指令层与自动记忆，提出提升、清理、冲突和归属不明的建议，在用户批准具体提案前不修改。该行为属于被迁入功能的用户交互规则，不要求为本次编码另加审批流程。只对当前用户可编辑层提交修改，不向匿名用户开放服务端公共系统提示词或仓库指令文件写权限。

Dream 提供状态详情与取消操作；日记模式和 Agent 快照提供实际可操作入口。管理接口均采用现有本地身份验证和服务器路径解析，不能暴露任意文件浏览器。

| 后台提取开关 | 源码实验配置回退关闭，另有构建与交互模式条件；本地显式配置 |

| 索引限制 | 200 行与 25,000 长度限制；源码所谓 bytes 实际使用 JavaScript 字符串长度，移植时不能隐含改成同数值 UTF-8 字节 |
| 索引单项描述 | 提示词约 150 字符一行；整理时处理超过约 200 字符的条目 |
| 扫描范围 | 每文件前 30 行，按修改时间降序最多 200 个候选 |
| 选择模型输出 | `max_tokens=256`，JSON schema 返回文件名；提示词最多选择 5 项，注入层再限制 5 项 |
| 单次正文注入 | 每文件最多 200 行、4096 字节，超限附读取完整文件说明 |
| 会话累计预取正文 | 60 × 1024；源码按已注入 `content.length` 累计，单位行为需核对后照迁 |
| 后台提取频率 | 默认每 1 个合格回合，保留可配置 N；尾随任务跳过此节流 |
| 提取轮数 | 最多 5 轮模型往返 |
| 提取退出收尾 | 排空函数默认上限 60 秒，接入宿主整体退出时限 |
| 自动整理门槛 | 至少 24 小时，并有至少 5 个其他会话在此期间被修改 |
| 自动整理扫描节流 | 10 分钟 |
| 整理锁持有过期 | 1 小时 |
| Dream 任务近期展示 | 最多 30 条助手回合 |
| 新鲜度提示 | 今天/昨天只标年龄，超过 1 天增加过时核验提示 |
